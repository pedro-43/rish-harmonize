# OpenNeuro Multi-Site Example (ds000206)

End-to-end `rish-harmonize` example on a publicly available multi-site diffusion
MRI dataset from [OpenNeuro](https://openneuro.org), reproducible from scratch
with just a download.

## Dataset

[**ds000206 — DWI Traveling Human Phantom Study**](https://openneuro.org/datasets/ds000206)
(CC0). Five healthy subjects were scanned at multiple imaging centres — a
**traveling-subject** design. Because the *same* subjects appear at every site,
any residual RISH difference between sites after registration is a pure
site/scanner effect with **no biological variability** to confound it — the
cleanest possible setting to demonstrate harmonization.

This example uses a balanced subset:

| | |
|---|---|
| Subjects | THP0001–THP0005 (5) |
| Sites | CCF, IOWA, MGH (reference = **CCF**) |
| Acquisition | `acq-GD31` run-01 — single-shell **b=1000**, 31 directions (→ lmax=6) |
| Sessions | 15 (5 subjects × 3 sites), ~640 MB |

> Single-shell is below the "multi-shell preferred" wishlist, but a 30-direction
> b=1000 shell is plenty to demonstrate the signal-level RISH pipeline, and the
> traveling-subject design more than makes up for it by isolating the site
> effect exactly.

## Requirements

- **MRtrix3** (`mrconvert`, `dwi2mask`, `dwi2tensor`, `tensor2metric`,
  `population_template`, `mrtransform`, `mrmath`, `mrcalc`, `mrstats`)
- **rish-harmonize** (`pip install -e ".[viz]"` from the repo root — `viz` is
  needed for the QC figures in step 8)
- ~640 MB disk for the download, plus ~1 GB for derivatives
- No ANTs/FSL needed — registration is done entirely with MRtrix
  `population_template`. Ran fine on a stock laptop (8 cores / 16 GB); see
  *Hardware notes* below.

## Quick start

```bash
# 1. Download the subset from OpenNeuro's S3 bucket (no datalad/openneuro-cli needed)
./download.sh

# 2. Run the whole pipeline, or a single step
./run_pipeline.sh            # all 8 steps
./run_pipeline.sh 6          # e.g. just the RISH-GLM step

# Point the scripts at your MRtrix3 / rish-harmonize install by putting them on
# PATH first (edit config.sh, or export PATH=... before running).
```

## Pipeline steps

Signal-level SH harmonization via the **RISH-GLM** joint model. MRtrix3-only;
registration uses `population_template` (`mrregister` under the hood).

| Step | What it does |
|------|--------------|
| 1. Prepare | Convert DWI→MIF (`mrconvert -fslgrad`), brain mask (`dwi2mask`), FA map (`dwi2tensor`+`tensor2metric`) per session |
| 2. RISH | `extract-native-rish` per session with `--consistent-with` (consistent lmax across all sessions) |
| 3. Template | Build an FA population template + per-session 5D warps (`population_template`, short nonlinear schedule) |
| 4. Warp | Warp native RISH + masks into template space (`mrtransform -warp_full`); intersect masks → group mask |
| 5. Manifest | Write the RISH-GLM `manifest.csv` (subject, site, rish_dir) |
| 6. GLM | `rish-glm --mode signal_rish` → per-site scale maps + fitted model |
| 7. Site effect | Permutation test of the l0 site effect, **pre vs post** harmonization (`site-effect`) |
| 8. QC | `qc-report` → scale-map heatmap + pre/post site-effect bar chart |

`manifest.csv` is regenerated by step 5; a copy of the one produced on the
reference run is checked in as `manifest.example.csv`.

## Results

Reference run (5 subjects × 3 sites, b=1000, lmax=6).

**Raw site differences** — mean RISH l0 in the group mask, before harmonization:

| Site | mean l0 | vs reference (CCF) |
|------|--------:|-------------------:|
| CCF (ref) | 733.2 | 1.00 |
| IOWA | 801.4 | +9% |
| MGH | 636.3 | −13% |

**Scale maps (l0)** computed by RISH-GLM correctly invert those differences:
IOWA → 0.949, MGH → 1.169.

**Site-effect reduction** (l0, 2000-permutation F-test over CCF/IOWA/MGH):

| | mean η² | median η² | sig. voxels (perm p<0.05) |
|---|--------:|----------:|--------------------------:|
| **Pre**  | 0.1959 | 0.1537 | 10.0% |
| **Post** | 0.0648 | 0.0437 | 0.4% |

➡️ **67% reduction in mean site effect**; significant voxels fall from 10.0% to
0.4%. Comparable to the UKB example's 64% / 59%.

QC figures land in `processing/qc_figures/`:
`site_effect_comparison.png`, `scale_map_heatmap_b1000.png`.

### Known limitation surfaced by this run

The **higher-order** scale maps (l2, l4) for IOWA hit the [0.5, 2.0] clip
**100%** of the time (the tool's own diagnostic warned about it). With a
single-shell b=1000 / 30-direction acquisition, the l4/l6 RISH features carry
little reliable angular energy, so their site ratios are dominated by noise.
The dominant, reliable **l0** order (above) is unaffected. For trustworthy
higher-order harmonization, use a higher-b / higher-direction acquisition. This
is a real property of low-angular-resolution data, not a pipeline bug — and a
good illustration of why the scale-map clipping diagnostic exists.

## Hardware notes

`population_template` (step 3) is the only compute-heavy step. It completed in a
few minutes on a stock laptop (8 cores / 16 GB) for this 15-session, single-
shell, small-FA workload using a short nonlinear schedule
(`-nl_scale 0.5,0.75,1.0 -nl_niter 5,5,5`). Cost scales with cohort size, image
resolution, and schedule length; for large cohorts or full nonlinear schedules,
run it on an HPC node (see `examples/ukb/submit_fa_pipeline.slurm`).
